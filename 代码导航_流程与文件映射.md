## 三、编排层三模块（简历核心增量）

| 模块              | 文件                             | 关键函数 / 结构                                                                                   | 职责                                                                                        |
| --------------- | ------------------------------ | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **编排单例**        | `infergateway/orchestrator.go` | `InitOrchestrator()` + 全局 `Checker` / `LB`                                                  | 单例入口：从 `INFERGATEWAY_INSTANCES` 环境变量加载实例池，启动 HC，创建 LB                                     |
| **健康检查**        | `health/checker.go`            | `HealthChecker` 结构 + `Start()` / `checkAll()` / `check()` / `Healthy()` / `MarkUnhealthy()` | goroutine + ticker 每 10s ping 所有实例 `/health`，连续失败 3 次标 DOWN，恢复自动标回。`RWMutex` 保护状态供 LB 并发读 |
| **负载均衡**        | `balancer/balancer.go`         | `LoadBalancer` 结构 + `Pick()` / `Failover()`                                                 | 加权轮询选实例（weight 越大被选中概率越高）；`Failover` 调 `MarkUnhealthy` 加速剔除故障实例                           |
| **gRPC 服务定义**   | `proto/infergateway.proto`     | `InferGatewayService` + `ChatRequest`/`ChatResponse`/`ListChannelsRequest`/`ChannelInfo`    | gRPC 服务契约，生成 `proto/infergateway.pb.go` + `proto/infergateway_grpc.pb.go`                 |
| **备用实例**        | `cmd/fakevllm/main.go`         | HTTP server :8001                                                                           | 模拟 vLLM 返回 mock 响应，用于 failover 演示                                                         |
| **gRPC client** | `cmd/grpcclient/main.go`       | `main` + flag `-addr`/`-token`/`-model`                                                     | 测试客户端，可调 `ChatCompletion` 和 `ListChannels`                                                |

### 编排层设计要点（面试可讲）

- **健康检查旁路**：HC 是后台 goroutine，不阻塞主链路；状态用 `RWMutex` 保护，LB 只读 `Healthy()` 列表
- **连续失败阈值**：单次抖动不误判，默认连续 3 次失败才标 DOWN
- **Failover 加速**：gRPC 链路 `DoRequest` 失败后调 `MarkUnhealthy` 立即剔除，不用等 HC 下一轮 ping
- **加权轮询**：weight 在环境变量配置，`http://localhost:8000,1;http://localhost:8001,1` 表示两个实例等权
- **绕过 Distribute 的原因**：Distribute 按 group 选厂商 channel（多厂商分发），编排层按实例健康度选 vLLM 实例（自建推理编排），两者职责正交，编排层独立是核心增量

## 七、关键设计决策（面试可讲）

1. **gRPC 复用 relay 链的方式**：mock `*gin.Context`（`httptest.NewRecorder` 作 Writer）喂给 `RelayTextHelper`，让 relay 链零修改复用。好处：鉴权、adaptor 转发、计费全流程一行不改；代价：流式响应暂时不支持（`httptest.Recorder` 不支持 flush，`ChatCompletionStream` 返 Unimplemented）
2. **编排层独立于 Distribute**：Distribute 管多厂商分发（按 group 选 channel），编排层管自建推理实例（按健康度选 vLLM）。两者职责正交，编排层独立是核心增量，不被渠道分发逻辑绑架
3. **failover 重试边界**：仅 5xx 或超时才 failover，4xx 是请求本身问题不重试。`Failover` 立即调 `MarkUnhealthy`，不用等 HC 下一轮 ping
4. **预扣 + 后扣 quota**：`preConsumeQuota` 按预估扣（防跑完不付钱），`postConsumeQuota` 按实际用量补差额。不够钱返 429 不打下游
5. **健康检查阈值**：连续失败 3 次才标 DOWN，避免单次抖动误判；不健康实例继续 ping，恢复自动标回
